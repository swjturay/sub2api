# AI基础设施看板：首版需求规格

状态：首版已实现并完成本地开发验证；按用户最新要求采用顶部导航并以 PC 为验收范围。开发及独立验证由 gpt-5.6-sol 子代理参与完成。尚未部署生产；验证证据与限制见 INSIGHTS_VALIDATION.md。

本文件是用户确认的首版实施与验收基线。后续范围修订须明确记录，不能以早期候选覆盖已确认决定。

## 1. 产品范围、入口和角色

原Sub2API网站同域 `/insights/`，原站普通跳转入口名为“AI基础设施看板”。React前端独立构建发布；后端Insights模块扩展在Sub2API内，沿用其账号、JWT、角色及数据授权。已登录无需再次登录，未登录或会话失效进入原登录流程，完成后返回原访问页面；需适配密码、2FA和已有OAuth登录返回及会话同步，不在URL传凭据。

| 角色 | 可见能力 | 默认页面 |
| --- | --- | --- |
| 普通用户 | 本人个人数据与日志；全系统模型目录、对比及获准的全平台模型聚合 | 个人数据 |
| 管理员 | 上述能力及部门数据、网关数据；个人页仍是自身数据 | 部门数据 |

四个固定分析页面，无拖拽布局、个人布局保存或管理员模板编辑。首版不提供CSV/XLSX/PNG/PDF等导出。没有新增部门负责人角色、公共分享、任意SQL、多数据源或独立身份系统。原站现有功能不因这些范围限制而被删除。

前端：React + TypeScript + Vite；界面：shadcn/ui + Tailwind；图表：ECharts。简体中文、蓝色主色、默认浅色并支持深色，以 PC 显示效果为首版验收范围（1366/1440/1920 等常见桌面宽度），不再进行手机端专项开发或验收；筛选靠近实际作用区域。具体依赖版本在实施时锁定验证。

## 2. 全局数据契约

### 2.1 统计时间与日期

所有请求相关分析统一按**统计记录时间**筛选和分桶。历史用量复用 `usage_logs.created_at`；新统一调用结果、同次用量及相关最终错误记录共用一次确定的统计时间，不由不同队列/重试分别取当前时间。无用量的失败调用在生成最终统计记录时赋值。

记录时间可能包含异步处理延迟，不称精确开始/完成时间，不用 `created_at − duration` 反推入口时间。首次请求、回访和留存的日期也使用统计记录时间。进行中不计为已有最终结果；未知或缺失结果提示不完整。统一的是分析时间，不更改耗时测量起止点、订阅账务或账号创建事件。

统一跟随平台配置时区；部署文件目前声明 `Asia/Shanghai`（UTC+8），并非已现场核验运行值。自然日零点、自然周周一零点、自然月1日零点；界面注明时区，首版无个人时区切换。筛选与分桶用同一边界，未来区间不当成已观察零值，尚未结束的桶标“未结束”。模型广场滚动24小时/7天仍为24/168小时。

### 2.2 Token与请求数量

令I为普通输入、W为缓存写入、R为缓存读取、O为输出Token，均取Sub2API归一化记录。

| 指标 | 公式与含义 |
| --- | --- |
| 总Token | I + W + R + O；缓存细分、已归入输出的推理Token不重复累加 |
| 输出Token | O的数量 |
| 缓存命中率 | ΣR / (ΣI + ΣW + ΣR)，先合计再求比；零分母为“—”，注明按网关记录统计 |
| 个人/部门用量请求次数、模型广场RPM来源 | 用量记录条数；有记录的失败/中断也可能计入，不等同全量调用或严格成功数 |
| 新网关调用次数 | 每次客户端模型调用的最终结果；内部重试归同一调用，客户端重新发起另计，WS按每次模型调用而不是连接 |

两种请求数量的数据范围不同，统一时间不将它们擅自混并。免费或零扣费的用量记录不得因 `actual_cost=0` 被排除。

### 2.3 用户、部门、模型

部门取既有用户扩展属性，按用户**当前单一部门**归集历史。完整路径 `A/B` 是一个部门，不自动计入祖先；单选以选项值识别、标签展示。空值归未分配，多值或绑定异常明确提示配置问题，不取首项、不分摊、不重复记账。用户转部门后历史重新归集；没有部门快照或任职历史。

部门、用户分析、模型偏好及漏斗的人群为当前未删除账号，含停用；多人多部门选择按用户ID去重。总成员数和网关期末总用户数的日期含义见各页面，不混用。

模型条目按平台＋规范化调用名称识别：同平台同名去重，跨平台同名和正式生产别名保留区分；不因共享上游目标就合并。统计与筛选必须使用相应模型身份，平台归属未知不伪造。全系统模型目录不改变实际调用授权，不向普通用户返回分组、账号或内部映射。

## 3. 个人数据

### 3.1 当天概览

固定今天、全部模型，不跟随历史日期或模型筛选。

- 每份有效订阅分别显示名称、当日已用金额/上限、进度条、剩余和重置时间。
- 使用真实订阅额度及其窗口；不以余额、API Key限额或日志金额求和代替，不另设费用看板。
- 并列显示当天总Token消耗，按统计记录时间归日。
- 订阅金额窗口与日志时间并非同一账务事件，跨零点时不承诺当日额度计数等于日志求和。

### 3.2 年度热力图

独立年份选择，默认今年，支持保留范围内年份。每日颜色深浅表示所有模型总Token，不跟随模型筛选。点击日期将下方历史统计和日志定位到该日，保留原模型选择。数据缺失、真实零消耗和未来日期分别呈现。

### 3.3 历史分析和日志

默认近7个自然日（含今天）、按天、全部模型。日期可选、粒度天/周/月，模型支持搜索和多选。多模型指标合并计算，模型分布仍展示各模型。

| 个人指标 | 定义 |
| --- | --- |
| 活跃天数 | 所选日期/模型范围内日总Token>0的自然日数，包括有记录消耗的失败或中断 |
| 总Token | 四项归一化Token合计 |
| 日均Token | 总Token/所选自然日数，包含零消耗日，排除未来日期 |
| 请求次数 | 筛选后的用量记录条数 |
| 输出Token | 输出数量，不显示个人输出占比 |
| 缓存命中率 | 全局约定的按量比例 |

总Token、输出Token、缓存命中率均可切柱状分布/折线趋势，使用相同时间分桶。模型调用分布以用量记录次数占比展示，标名称/百分比；悬浮有次数、总Token、输出Token。

日志仅本人，分用量/错误两页签，共用日期/模型筛选，时间倒序分页，可展开元数据。用量字段：统计记录时间、当前部门、模型、API Key名称、普通输入/输出/缓存读写Token、调用耗时、首Token耗时。错误字段：时间、模型、错误类型、简要原因。仅复用现有duration/TTFT，不新增个人网关耗时列，不展示对话正文或Key秘密，无导出。

## 4. 模型广场

展示代码仓内明确维护的正式生产模型，不按用户分组、订阅或部门裁剪。目录不从账号映射、渠道配置、请求历史或测试数据自动发现名称；内部测试名称不进入目录。

资料仅依据模型厂商官方来源整理，随代码评审更新，保留来源与目录更新时间。详情为只读，管理员没有编辑入口；不增加自动检查或定时同步机制。别名对应目标不确定时保留缺失状态。未知能力不等于不支持；没有参考价不等于免费。

参考价格复用Sub2API全局参考价，注明原单位和适用条件；不以分组最低价或个性化实际扣费代替，不在Insights另设改价流程。不同单位/阶梯不得压成一个没有条件的数字。

所有用户可查看相同的全平台按模型聚合指标，不能查看其他用户原始日志。窗口为滚动24小时/7天，趋势分别每小时/每天一个点。

| 性能指标 | 计算 |
| --- | --- |
| 平均TPM | 窗口总Token/窗口分钟数，含无流量分钟 |
| 平均RPM | 窗口用量记录数/窗口分钟数，不额外加错误日志 |
| 平均TTFT | 有效、非负、非空首Token耗时的逐请求算术平均 |
| 估算TPOT | 每条有效流式记录先算(duration−TTFT)/(输出Token−1)，再等权平均；输出>1、计时有效且duration>TTFT |

无有效时长样本显示“—”，空闲时段不作0毫秒样本；不平均各时间桶的均值，也不称GPU纯解码性能。TTFT沿现有协议采集边界，TPOT明确标估算。

模型对比支持2–4个模型，资料、能力、参考价及四项平台指标并排；共享24小时/7天窗口，每项性能趋势叠加所选模型并保持颜色一致。不触发模型测试或付费推理。

## 5. 部门数据

部门全部/单选/多选；默认近7个自然日含今天、按天、全部模型。支持日期、天/周/月及模型多选，当前部门归集规则适用于所有历史范围。

| 部门指标 | 定义 |
| --- | --- |
| 总成员数 | 当前所属、未删除、含停用人数，不随日期或模型改变 |
| 活跃成员数 | 上述人群在所选日期/模型有Token>0的去重人数 |
| 总Token、日均Token | 四项Token之和；日均除以所选自然日数 |
| 每日人均Token | 总Token/自然日数/总成员数，不以活跃人数作分母 |
| 请求次数 | 人群及筛选范围内的用量记录条数 |
| 输出Token、输出Token占比 | 输出数量；Σ输出/Σ总Token |
| 缓存命中率 | 统一按量公式 |

部门不展示活跃天数。比率或人均分母为零显示“—”。模型分布按用量记录次数占比。

- 帕累托可切部门/成员：全部或多部门默认部门，单部门默认成员；总Token降序柱形、累计占比线和80%参考线，分母为完整筛选范围的总消耗。
- TOP10仅用户名、总Token和横向柱状条，按总Token降序，人数不足按实际；无成员下钻。
- 性能区使用**独立的全部/单模型选择器**，默认全部，只显示一组平均TPM/RPM/TTFT/估算TPOT。跟随部门和日期，不受页面其它区域模型多选影响；按有效原始样本合计，不直接平均模型均值。

## 6. 网关数据

默认近7个自然日含今天、按天、全部部门。快捷今天/近7天/近30天及自定义日期；粒度小时/天/周/月；部门全部/单/多选及搜索，含未分配部门。粒度只改变请求成功率和用户数趋势，不重算频次阈值。

### 6.1 请求质量

显示请求总次数、失败次数、成功率及趋势、模型平均处理时长、网关平均处理时长。

| 规则 | 定义 |
| --- | --- |
| 成功 | 模型调用正常完成并返回结果 |
| 失败 | 拒绝、报错、超时、流中断或客户端完成前取消/断开；HTTP200本身不保证成功；拒绝指调用接口层面的拒绝，不对回答正文质量作语义判断 |
| 总次数与成功率 | 总次数=成功+失败；成功率=成功/总次数；进行中不计，无样本“—” |
| 全部部门 | 全网关已有明确结果的模型调用，含身份未知及已删除用户历史 |
| 指定部门 | 当前所属且未删除成员，含停用；身份未知不混入未分配部门 |

全网关总数可大于各现有部门之和，需注明口径。控制台访问、健康检查和WS连接本身不算模型调用；内部重试不增加客户端调用次数。未知终局/采集缺失标不完整，不伪造严格成功率。

两类平均时长仅取最终成功调用的有效样本：模型时长为最终成功上游尝试从实际发送到完整响应/流终止，标“网关观测值”；网关时长为接收到首次实际上游发送，含认证/解析/调度/排队，标“转发前，含排队”。内部失败尝试不加到模型时长，响应转发不属于该网关时长；二者不相加称端到端总等待。缺失不填零。

不提供SLA参考值、错误率/错误记录数、业务限制数、上游429/529次数或额外QPS/TPS套餐。

### 6.2 用户分析

人群为当前未删除、含停用、当前部门归属、截至所选期末已创建的账号。

- 总用户数：截至所选期末的该人群人数。
- 用户数趋势：各时间桶结束时累计已创建人数；按当前名单回看，不是假称不可变历史在册快照。
- 新增用户数：区间内创建的Sub2API账号数。
- 高频>200次，中频20–200次含两端，低频0–19次含未使用者。
- 频次按整个所选区间成功+失败调用累计；切粒度不重分类，完整数据下三类覆盖期末人群。未采集不当零次。

### 6.3 用户转化漏斗

五层：总用户数→首次请求人数→次日留存→7日留存→30日留存。按所选**结束日期的累计快照**，开始日期不截断历史；统一观察截止，图形宽度按去重人数，各层显示人数及占总用户数比例。

首次层是总用户集合中截至该时至少有一次调用统计记录的用户，成功/失败均可；最早可信统计记录日为第0天。第N日留存定义为第N个自然日及以后至少再次有调用统计记录。一次第30日回访同时满足三层，不要求恰好第1、第7日调用。

所以30日⊆7日⊆次日⊆首次请求⊆总用户，允许相等、不向下增加。不将各自成熟分母的独立留存率拿来画递减宽度；不排序或篡改独立数值制造漏斗。未到期标待观察，真实首次或回访覆盖不足标数据不完整，不用上线后首次观察冒充真实首次。

### 6.4 部门模型偏好

当前人群按整个起止区间的成功+失败调用统计，模型以平台/调用名称识别。每部门一条100%横向堆叠条，分母为本部门总调用；部门按总次数降序。旁边显示部门总次数，悬浮模型名/次数/部门内占比，未分配部门单列；无请求不伪造占比。

## 7. 刷新、覆盖和保留

指标与图表默认60秒自动刷新，可关闭；初次加载/筛选变化立即读取，提供手动刷新。后台暂停，重新可见时更新。日志手动刷新/按需加载，保持分页和阅读；数据刷新不清筛选、模式或年份。显示最近成功刷新时间；失败保留旧数据并标未更新，延迟/未采集/不完整分别提示。60秒是刷新间隔，不是采集落库时延保证。

| 数据 | 保留 |
| --- | --- |
| 用量明细、新统一调用结果明细 | 365天 |
| 错误明细 | 30天 |
| 新用户/模型日统计 | 今年及前两个完整自然年 |
| 可信首次/留存达成统计时间及覆盖状态 | 账号存续期间 |

超明细期只提供已保留的日/周/月统计，不伪造小时桶或明细。新日统计需保留用户/模型维度、各指标合计/样本数/覆盖状态；已有全站730天汇总不能替代。首次/留存需保存达成时刻，而非仅当前最后活跃，才能回看历史截止。

可信原始数据可分段初始化；已清理或未采集的数据标缺失，不补零。新增最终结果、精确新阶段计时等从真实采集启用后覆盖，不从旧usage/错误拼接伪造历史。清理前验证需长期保存的汇总和事实已可靠形成。

## 12. 验收场景

1. 普通用户只读本人日志；全平台模型聚合可读，其他用户明细及管理员数据不能越权；原登录、角色变化、失效、退出和多标签刷新行为正确。
2. 同一新调用的结果和用量共享统计时间；跨日按记录日统一，异步和重试不产生新的日期口径；时区和周/月边界一致。
3. I=100、W=20、R=30、O=50时总Token=200、缓存率=20%、部门输出占比=25%；个人显示输出50。无分母、无样本与零值正确区分。
4. 个人热力图始终所有模型；点击日期只按既定规则更新下方；部门性能模型选择不受页面其它模型多选影响。
5. 部门转移重算历史，停用包含、删除从当前成员分析排除但保留全网关历史；完整路径不重复归祖先，空值与绑定错误不同。
6. 高频边界0/19/20/200/201正确，按整个区间计数；期末总人数排除之后新建用户，趋势是累计人数。
7. HTTP流式/非流式及WS调用均按定义产生最终结果；内部重试不重复，HTTP200中断/客户端取消不误判成功，未知结果不冒充完整成功率。
8. 模型时长取最终成功尝试，网关时长止于首次发送；成功样本均值、TPM/RPM零流量分钟、TTFT/估算TPOT有效样本和跨桶加权均正确。
9. 第30日及以后回访同时进入三层，截止之前没有达成则不能使用之后的回访；未到期/首次未知/缺失不伪造成流失或0。
10. 原始明细清理后，保留范围内个人日历及当前部门/模型日统计仍有依据；超过小时/明细保留明确限制；旧记录无法生成的新指标标未采集。
11. 正式模型白名单完整，内部测试名称不进入目录；同平台同名去重、不同正式别名/平台区分；资料仅引用官方来源且只读，参考价单位与缺失状态正确；无实际推理测试调用。
12. 刷新不丢筛选或分页；失败保留旧值并提示；深浅色及常见 PC 分辨率下可读、可操作，图表和表格均没有导出入口。
