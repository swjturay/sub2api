# CPR 保持一对一绑定，Sub2API 保留业务控制与协议转换

用户于 2026-09-30 明确继续采用一对一 CPR 账号绑定，并选择以 KLNO 为基础定向移植。Sub2API 负责用户、账号选择、计费、并发控制与非 Responses 协议转换；CPR 负责真实账号及其出站执行。采用独立原生中继并保留兼容转换路径，共同执行模块不作为引入前置，以保留现有业务扩展并控制改动范围。

一对一关系必须由 CPR client key 的实际授权范围保证，不能仅靠绑定记录中的账号 ID。原生中继仍在 Sub2API 的业务控制与结算范围内；把 CPR 配置为无固定真实账号的聚合池需要另行改变此决策。
