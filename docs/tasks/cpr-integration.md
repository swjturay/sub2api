- 客户端断连后，CPR 原生与兼容转换请求统一立即取消上游；保留已观测用量并标记用量完整性（第一轮 Q1 已确认）。

- 用量完整性仅管理员可见；用户界面保持现状，普通用户接口不新增该管理员信息（第二轮 Q4 已确认）。
- 故障切换采用 KLNO 行为与现有配置次数；不新增一次上限，也不采用“执行结果不确定就一律失败”的收紧策略。客户端取消后、已输出生成结果后不重放（第二轮 Q5 已确认）。

## 第一轮问题与建议

| 问题 | 建议 | 状态 |
| --- | --- | --- |
| Q1 客户端断连后的行为 | 原生与转换请求统一立即取消上游；记录已观测用量，未取得终态单独标记 | 用户已确认 |
| Q2 已有实际 usage 的失败/取消请求 | 按已确认消耗结算，保留失败/取消状态；本地估算不得冒充实耗 | 用户已确认 |
| Q3 “模型映射不必要”的含义 | 本次不扩展映射，保留已有规则并支持实际模型同名 | 用户已确认 |

此前研究把“模型映射不必要”进一步解释为“所有 CPR 路径强制同名”。这不是已经确认的用户决定，本轮显式消除该歧义。

本轮事实核对：当前 `openai_gateway_handler.go` 的 Responses 取消及普通错误分支都会提交非空 result 的 usage；`RecordUsage` 不因失败 outcome 自动免单，普通计费链未发现自动退款规则。Q2 推荐项延续现有政策，修复重点是已知 usage 在错误返回中丢失的缺口。

2026-09-29 的已记录生产快照显示 composite 19/20/21 依赖 Claude 前缀到 GPT 的渠道映射，所查 CPR 账号自身 mapping 为空；强制同名将涉及现有客户端兼容。该快照不是实时在线配置保证。

当前执行结果与 Insights outcome 均无法准确表达“上游用量完整/部分/未知”；outcome 是请求结果，用量完整性是另一维度。实现需要显式保留观察状态，不能把 0 token 或 cancelled 直接解释成用量未知。现有 CodexObservation 是安全与路由信息，不应直接用它控制收费；本次使用其管理员专属 JSONB 扩展记录完整性，实际结算仍读取独立的真实 Usage；无需新增数据库迁移。

## 第二轮问题与建议

| 问题 | 建议 | 状态 |
| --- | --- | --- |
| Q4 用量完整性标记展示对象 | 用户选择仅管理员可见，用户界面保持现状；普通用户接口不新增该管理员信息 | 用户已确认 |
| Q5 响应前连接中断且执行结果不确定时是否换绑定 | 用户选择沿用 KLNO 与现有配置的切换次数；不新增一次限制；已输出或客户端已取消时不重放 | 用户已确认 |

Q5 与 donor 的重要差异：donor 对响应前一般传输错误会请求外层 failover；连接错误并不总能证明上游未执行。DNS/连接拒绝与请求发出后的超时、断线须区分，不能把“未收到响应”直接等同“未产生消耗”。

Q5 最终选择沿用 KLNO/现有配置的切换次数。用户已了解不重试会直接返回失败，选择保留响应前传输异常的自动切换能力。该策略改善连续可用性，但不能承诺前一次请求没有产生消耗；已确认的消耗仍遵循 Q2，未知用量不得虚构。

## 最终确认的具体落地范围

- 原生 Responses HTTP/SSE 与 WebSocket：移植 KLNO 原样中继结构，接回现有鉴权、调度、分组政策、计费、Insights 与管理员观测。只面向 CPR，不顺带增加 API-key raw 开关或自动 turn-state 注入。
- Chat / Messages：保留两端协议转换与既有映射，修复完整历史、不必要的 todo guard、失败用量丢失；CPR 分支取消时停止上游，不继续后台 drain。
- 计数接口：保留 CPR 已有的 Responses input_tokens 本地估算，补齐 Messages count_tokens 本地估算，避免请求 CPR 不存在的端点；计数不作为生成收费依据。
- 并发：同时处理用户槽、账号槽以及 WS 每轮槽，等待阶段取消可退出，CPR 开始执行后由执行收尾释放；取消与进入执行态的竞争必须有回归。
- 计量：已收到 usage 的观察先于写下游；终态缺失不标成正常成功；完整、部分、未知与历史未记录分开。管理员可查，普通用户界面和专属字段访问保持现状。
- 重试：沿用 KLNO 分类与现有配置次数，不加一次上限；保留一对一绑定和被动会话来源校验。
- 已有图片与搜索专用接口保留；本次不新增 CPR 服务端不支持的协议端点或伪造 legacy compact 成功。
- 用本地 mock、数据库字段/DTO 权限回归、前端检查及后端构建验证；真实 CPR 的取消时延和计费一致性必须单独标明是否已验证，不以 mock 代替。
- 完成本地实现和可审阅验证报告；自动补账、CPR 内核改造和生产切换不在本次默认范围内。

## 已有证据与实现必须解决的问题

上一轮 donor 验证共 32 个顶层测试通过，包括 28 个 donor 测试与 4 个研究探针。探针通过意味着复现行为，不代表缺陷已修。

- Messages 的 15 条历史被裁为 12 条，再插入 todo guard；需完善完整上下文的兼容处理。
- Chat / Messages 普通 buffered failed 即使上游带 usage 仍返回 nil result，导致已知用量不能交给外层结算。
- 原生 SSE 先写下游再解析 usage，写失败可能丢掉已经收到的计量；应保证已接收用量不受下游写结果影响。
- 原生 SSE 未收到终态即 EOF 可被内部视为成功；必须正确标记未完成。
- 转换请求可在客户端断连后继续读取上游，而外层执行占用提前释放；须按选定取消策略修正。
- 原生 CPR relay 不得绕过本站准入或引入直连 OAuth 身份改写；不得覆盖 CCE 的 Insights 与观测扩展。

## 本地落地结果

- 原生中继：[HTTP/SSE](../../backend/internal/service/openai_raw_relay.go)、[WebSocket](../../backend/internal/service/openai_raw_relay_ws.go)。基于固定 donor 定向移植，仅 CPR 启用；保留未知字段、原始压缩和上游事件，继续应用本站权限、映射和分组政策。
- 转换与计数：Chat/Messages 继续转 Responses，15 条历史完整保留且不附加 todo guard；CPR Messages 本地计数与现有 Responses 本地计数并行，不向 CPR 发送不支持的计数端点。
- 计量：[CPR usage capture](../../backend/internal/service/openai_cpr_usage.go) 在读取上游字节时观察，早于下游写入；逐字段接受有效数值，拒绝数字字符串/空对象等伪计量。SSE 整帧观测上限 16 MiB，超限保留透传并明确未知，不无限累积。
- 结算：HTTP 每次已发出的 CPR 尝试和 WS 每轮有独立 BillingRequestID；同一结果重复提交保持同一个键。实际计量与完整性分别存储，失败、取消和 Cyber 都保留已取得消耗。Cyber 告警保持，消除第二条不完整账单。
- 并发：[execution lease](../../backend/internal/handler/openai_execution_lease.go) 区分等待与执行；取消不会提前归还执行中的 CPR 用户/账号槽。释放与取消竞争通过同一个 once 同步；HTTP 关闭等待在途读取观察完成，WS 关闭立即取消且不 drain。
- 观测：复用既有 codex_observation JSONB，管理员展示完整/部分/未知及终态；普通用户 DTO 不返回该字段。CPR 内部 hop 不推导 OpenAI 路由摘要，推理头不更新 Admin API 配额快照。无需数据库迁移。
